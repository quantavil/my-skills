# Core Taste Guide: anti-slop pages and redesigns

Scope: landing pages, portfolios, redesigns. NOT dashboards, data tables, multi-step product UI — route those to a real design system (§2) and apply this guide only to their marketing surfaces.

## 0. Brief inference (do this before generating anything)

Read these signals first: page kind (landing SaaS/consumer/agency/event, portfolio dev/designer/studio, redesign preserve vs overhaul, editorial/blog); vibe words verbatim; reference signals (URLs, screenshots, named products, competitors); audience; existing brand assets (starting material for redesigns). Quiet constraints OVERRIDE aesthetics: accessibility-first, public-sector, regulated, trust-first commerce, kids.

Emit a one-line Design Read before generating:

`"Reading this as: <page kind> for <audience>, with a <vibe> language, leaning toward <design system or aesthetic family>."`

If genuinely divergent, ask exactly one clarifying question (e.g. `Should this feel closer to Linear-clean or Awwwards-experimental?`). If inferable, do not ask.

Anti-default discipline: never ship AI-purple gradients, a centered hero over dark mesh, three equal feature cards, generic glassmorphism everywhere, infinite-loop micro-animations, or Inter + slate-900 by default.

## 1. Configuration: dials + variance engine

Set the three dials (baseline `DESIGN_VARIANCE 8 / MOTION_INTENSITY 6 / VISUAL_DENSITY 4` unless the design read overrides). Exact names mandatory — never alias. Inference: minimalist/clean/calm/editorial/Linear → 5-6 / 3-4 / 2-3; premium/Apple/luxury → 7-8 / 5-7 / 3-4; playful/wild/Dribbble/Awwwards/agency → 9-10 / 8-10 / 3-4; landing/portfolio default → 7-9 / 6-8 / 3-5; trust/public-sector/regulated/a11y → 3-4 / 2-3 / 4-5; redesign-preserve → match / +1 / match; redesign-overhaul → +2 / +2 / match. Presets: SaaS landing 7/6/4; agency 9/8/3; premium consumer 7/6/3; designer portfolio 8/7/3; dev portfolio 6/5/4; editorial 6/4/3; public-sector 3/2/5.

Bands: VARIANCE 1-3 symmetric/predictable; 4-7 offset (overlaps, mixed aspects, left headers); 8-10 asymmetric (masonry, `2fr 1fr 1fr`, massive voids). MOTION 1-3 static (hover/active only); 4-7 fluid CSS (`transition:all 0.3s cubic-bezier(0.16,1,0.3,1)`); 8-10 choreography (scroll reveals, GSAP). DENSITY 1-3 gallery (`py-32`–`py-48`); 4-7 daily app (`py-16`–`py-24`); 8-10 cockpit (tight, no cards, 1px separators, `font-mono` for all numbers). Asymmetric layouts MUST collapse to single-column `w-full px-4 py-8` below `768px`.

Then roll the variance engine silently: pick ONE vibe archetype and ONE layout archetype, and never generate the same combination twice in a row.

- **Ethereal Glass (SaaS/AI/tech):** deepest OLED black (`#050505`), radial mesh gradients (subtle glowing purple/emerald orbs), vantablack cards with heavy `backdrop-blur-2xl` and white/10 hairlines, wide geometric grotesk type.
- **Editorial Luxury (lifestyle/real-estate/agency):** warm creams (`#FDFBF7`), muted sage or deep espresso, high-contrast variable serif massive headings, CSS noise overlay (`opacity-[0.03]`) for paper feel.
- **Soft Structuralism (consumer/health/portfolio):** silver-grey or white backgrounds, massive bold grotesk, airy floating components with soft diffused ambient shadows.
- **Asymmetrical Bento:** masonry-like grid of varying card sizes (`col-span-8 row-span-2` beside stacked `col-span-4`); mobile falls back to `grid-cols-1`, all spans reset to `col-span-1`.
- **Z-Axis Cascade:** cards stacked with overlap, varying depth, subtle `-2deg`/`3deg` rotation; mobile removes rotations and overlaps (touch-target conflicts).
- **Editorial Split:** massive type left (`w-1/2`), scrollable image pills or staggered cards right; mobile becomes full-width vertical stack.

## 2. System routing: honesty rule

If the brief matches an official system, install and use the official package — do not hand-recreate its CSS, do not import tokens then override 90%, one system per project. Microsoft/enterprise → `@fluentui/react-components`; Google-ish → `@material/web` + M3 tokens; IBM B2B/analytics → `@carbon/react`; Shopify → Polaris; Atlassian-style → `@atlaskit/*`; GitHub devtool → `@primer/react-brand` or css; UK public-sector → `govuk-frontend`; US/trust-first → `uswds`; local-business MVP → Bootstrap 5.3; accessible React foundation → `@radix-ui/themes`; owned modern SaaS → shadcn/ui (never ship default state); Tailwind SaaS marketing → Tailwind v4 + `dark:` variant.

Aesthetics with NO official package are built native (CSS + Tailwind + maintained libs), with borrowed inspiration labeled honestly: glassmorphism = `backdrop-filter` + layered borders + solid fallback under `prefers-reduced-transparency`; Bento = CSS grid mixed cells; brutalism = native CSS/mono/raw borders; editorial = serif + asymmetric grid + whitespace; dark tech = mono + neon + terminal; aurora = SVG/layered radial; kinetic = native CSS/scroll-driven, GSAP only for hijacks. Apple Liquid Glass is Apple-platforms-only — there is no `liquid-glass.css` for web; any web version is an approximation and must be labeled as such.

## 3. Stack conventions

React or Next.js, Server Components by default: global state ONLY in Client Components; motion/scroll/pointer physics MUST be isolated leaf `'use client'` components, server renders static only. Tailwind v4 default (v3 only if the project demands); with v4 use `@tailwindcss/postcss` or the Vite plugin, never the `tailwindcss` postcss plugin. Animation via Motion (`import { motion } from "motion/react"`, not the `framer-motion` alias in new code). Fonts via `next/font` or self-hosted `@font-face` + `font-display: swap`; never `<link>` Google Fonts in production. Local `useState`/`useReducer` for isolated UI; global store only for deep drilling. NEVER `useState` for continuous input-driven values (mouse, scroll, pointer physics, magnetic hover) — use `useMotionValue`/`useTransform`/`useScroll`. Icons: `@phosphor-icons/react`, `hugeicons-react`, `@radix-ui/react-icons` or `@tabler/icons-react` — one family per project, one global `strokeWidth` (1.5 or 2.0); `lucide-react` only on explicit request; NEVER hand-roll SVG paths. Emoji discouraged in code and visible text (playful/chat contexts only, sparingly). Breakpoints `sm 640 / md 768 / lg 1024 / xl 1280 / 2xl 1536`; contain with `max-w-[1400px] mx-auto` or `max-w-7xl`; hero uses `min-h-[100dvh]`, NEVER `h-screen`; grid over flex-math (never `w-[calc(33%-1rem)]`). Before importing ANY third-party library, check `package.json` and output the install command first.

## 4. Typography

Display default `text-4xl md:text-6xl tracking-tighter leading-none`; body `text-base text-gray-600 leading-relaxed max-w-[65ch]` (≈65 characters). Sans first: `Geist, Outfit, Cabinet Grotesk, Satoshi` (pairs: `Geist+Geist Mono`, `Satoshi+JetBrains Mono`, `Cabinet Grotesk+Inter Tight`). Inter only on explicit neutral/Linear-style request or accessibility-first briefs. Serif ONLY if the brief names serif or the project is genuinely editorial/luxury/publication/heritage — "creative feel" alone is not justification; rotate the serif pool (`PP Editorial New, GT Sectra, Tiempos, Recoleta, Cormorant, Playfair, Canela…`), never reuse consecutively, and NEVER `Fraunces` or `Instrument_Serif` as defaults. Emphasize with italic/bold of the SAME family — never inject a random serif word into a sans headline. Italic display containing `y g j p q` with `leading-none` clips descenders: use `leading-[1.1]` minimum + `pb-1` reserve, and audit every italic display word. Use Medium (500)/SemiBold (600), not just 400/700. Numbers in data UI get tabular figures (`font-variant-numeric: tabular-nums`) or mono. Negative tracking for large headers, positive for micro-labels; avoid all-caps-everywhere (try sentence case, lowercase italics); fix orphans with `text-wrap: balance`/`pretty`.

## 5. Color

Max ONE accent, saturation below 80%, one gray family (never mix warm/cool), one palette per project, accent locked across the whole page. Bases: zinc/slate/stone + singular high-contrast accent (emerald, electric blue, deep rose, burnt orange). No default AI purple/blue glow, purple button glows, or random neon gradients — unless the brief explicitly asks purple, then harmonized and restrained. For premium-consumer briefs (cookware, wellness, artisan, luxury, DTC) the beige-background + brass-accent + espresso-text default is banned (no `#f5f1ea`-family backgrounds, `#b08947`-family accents, `#1a1714`-family text); rotate alternatives (cold luxury silver+chrome, forest green+bone+amber, black+tan, cobalt+cream, terracotta+slate, olive+brick+paper, monochrome + one saturated pop) and never serve the same warm-craft family twice in a row. Tint shadows to the background hue (never pure-black shadows on light); one consistent light direction; no random dark section inside a light page (tint within the palette instead). Pure `#000000` banned — use off-black/charcoal/tinted dark (`#0a0a0a`, `#121212`, dark navy).

## 6. Layout

Force asymmetry when VARIANCE > 4: split 50/50, left-content/right-asset, asymmetric whitespace, scroll-pinned — centered heroes only for editorial/manifesto/launch where the message IS the design. Three equal feature cards is the most generic AI layout: use 2-col zig-zag, asymmetric grid, horizontal scroll, or masonry instead; bento MUST have rhythm (vary full-width/asymmetric/vertical breaks, never 6× left-image/right-text) with exactly N cells for N items and ≥2–3 cells carrying real visual variation (image, brand gradient, pattern, tint — never 6 white text cards). Each layout family max ONCE per page (an 8-section landing needs ≥4 families); max 2 consecutive image+text-split sections (3rd in a row fails — break with full-width, vertical stack, bento, or marquee). The `left-headline + right-small-paragraph` split-header is banned by default — stack headline + body (≤65ch) unless the right column carries a visual. Eyebrows rationed: max 1 per 3 sections, signature `text-[11px] uppercase tracking-[0.18em]` (hero counts as one). No `border-t` AND `border-b` on every long-list row — pick one, sparse. Cards exist ONLY when elevation communicates real hierarchy — else `border-t`/`divide-y`/negative space; one radius scale page-wide (all-sharp, all-soft 12–16px, or all-pill, mixed only under a documented rule). Vary radii inward (tighter inside, softer outside). Let sections breathe (`py-24` minimum for premium); overlap with negative margins for depth; align shared elements (titles, prices, buttons) across side-by-side cards and pin card CTAs to the bottom. Center by eye, not by math (1–2px optical corrections on icons-in-text, play buttons, button labels). Mobile: every multi-column section declares its `<768px` collapse in the same component.

Hero contract (all must hold): fits the initial viewport — headline ≤2 lines desktop, subtext ≤20 words AND ≤4 lines, CTAs visible without scrolling; type planned with imagery (a >6-word headline is never `text-7xl/8xl`; default `text-4xl md:text-5xl lg:text-6xl`); top padding capped at `pt-24`; max 4 text elements (eyebrow OR brand strip, headline, subtext, 1 primary + max 1 secondary CTA) — banned from heroes: tagline below CTAs, trust micro-strips, pricing teasers, feature bullets, avatar rows; used-by logo walls go UNDER the hero, never inside, logo-only (no industry labels under logos, real SVG marks via Simple Icons/devicon or invented monograms — never plain `<span>` wordmarks, must render in light AND dark). Desktop CTAs must be one line (shorten to ≤3 words or widen the button — a wrapped CTA fails pre-flight) and one label per intent page-wide. Nav: single line at desktop, ≤80px tall (default 64–72px), condense or hamburger otherwise.

## 7. Haptic construction (premium builds)

Never place a card, image, or container flat on the background: build the Double-Bezel — outer shell (`bg-black/5` or `bg-white/5`, hairline `ring-1 ring-black/5` or `border-white/10`, `p-1.5`/`p-2`, `rounded-[2rem]`) around an inner core with its own background, inner highlight (`shadow-[inset_0_1px_1px_rgba(255,255,255,0.15)]`), and concentric radius (`rounded-[calc(2rem-0.375rem)]`). Primary buttons are `rounded-full px-6 py-3` pills; a trailing arrow NEVER sits naked — nest it in its own flush circular island (`w-8 h-8 rounded-full bg-black/5 dark:bg-white/10`). Precede major headings with a microscopic pill eyebrow (`rounded-full px-3 py-1 text-[10px] uppercase tracking-[0.2em] font-medium`).

## 8. States, robustness, motion

Every interactive element ships full cycles: hover (background shift/scale/translate), tactile `:active` (`scale-[0.98]` or `-translate-y-[1px]`), visible focus rings (non-optional accessibility), loading as skeletons matching final shape (no generic spinners), composed empty states (never a blank dashboard), inline form errors (never `window.alert()`), dead `#` links either wired or visibly disabled, active-nav indication, `scroll-behavior: smooth`. Button and form contrast MUST pass WCAG AA (4.5:1 body, 3:1 large) — bans white-on-white, transparent-on-background without border, ghost-over-photo without scrim, light placeholders on near-white. Forms: label above, error below, `gap-2` blocks, never placeholder-as-label.

Motion must be motivated (one sentence per animation: hierarchy, storytelling, feedback, state transition) and motion claimed must be motion shown (MOTION > 4 with a static page is broken — drop to 3 if it can't ship working motion). Animate ONLY `transform` + `opacity` (never `top/left/width/height`, never `window scroll` listeners or state-touching rAF loops); `will-change: transform` sparingly on actually-animating elements. Signature moves: magnetic hover via motion values off-render (MOTION > 5, premium/playful only); perpetual loops (pulse, float, shimmer, marquee) only where the section earns it — MARQUEE MAX ONE PER PAGE; scroll entries as gentle heavy fade-ups (`translate-y-16 blur-md opacity-0` → clear over 800ms+) via `whileInView`/IntersectionObserver, or GSAP+ScrollTrigger pinned sequences (`trigger: <wrap> start:"top top"`, real pin, scrub, `ctx.revert()` cleanup) — never mix GSAP/Three with Motion in the same tree. If MOTION > 3, `useReducedMotion()` → static is non-negotiable (CSS gated behind `prefers-reduced-motion`, loops/parallax/hijacks collapse). `backdrop-blur` on fixed/sticky elements only (nav, overlays) — never scrolling content; grain overlays only as fixed `pointer-events-none` layers, never in scrolling containers. z-index reserved for systemic layers (document the scale; no `z-50`/`z-[9999]` spam). LCP < 2.5s (hero `priority`/preload), INP < 200ms, CLS < 0.1 — run Lighthouse before done. Dark mode is mandatory for consumer surfaces: one token strategy (Tailwind `dark:` OR CSS vars, set once), hierarchy/brand/AA preserved, no pure black/white, both modes visually tested.

## 9. Content discipline

One copy register per page. Re-read every string: no broken grammar, no unclear referents, no hallucinated metaphors, no "thoughtful LLM" voice — plain functional sentences when unsure. Fake-precise numbers (`92%`, `4.1×`, `48k`) ONLY from real data or explicitly labeled mock. Names, avatars, dates, brands must feel real: no John Doe/Sarah Chan, no egg avatars, no identical blog dates, no Acme/Nexus/SmartFlow, no stock "diverse team" photos, never Lorem Ipsum — write real draft copy. Banned copy words: Elevate, Seamless, Unleash, Next-Gen, Game-changer, Delve, Tapestry, "In the world of…". Sentence case headers, not Title Case. No "Oops!", no exclamation-loud success copy, active voice ("We couldn't save your changes"). Quotes ≤3 lines with name+role(+company) attribution, real typographic quotes (“ ”), and NO em-dashes inside — in fact the em-dash `—` is banned EVERYWHERE on the page (headlines, buttons, captions, nav, body, alt text), en-dash as separator banned too; ranges use hyphens (`2018-2026`). One `—` anywhere fails pre-flight.

Density: per section, headline ≤8 words + sub ≤25 words + one visual OR one CTA; no data dumps (20-row tables, giant pricing matrices) — Top 3–5 + view-full link, marquee/carousel, tabs/accordion, scroll-snap pills, or a separate page. More than 5 items is never a default `<ul>`: group, grid, or paginate. Testimonials: masonry wall, embedded posts, or single rotating quote — not 3-card dot carousels. Pricing: highlight the recommended tier with color and emphasis. Modals are a last resort (inline editing, slide-overs, disclosure first).

Images: if an image-gen tool is available it MUST be used at correct aspect; else real web sources (`https://picsum.photos/seed/{descriptive-seed}/{w}/{h}`, brand URLs, direct Unsplash/Pexels) — even restrained/minimal pages need ≥2–3 real images; else an explicit labeled TODO plus a closing list of needed shots. Never div-fake screenshots, never hand-rolled decorative SVG (library icons fine), never text-only heroes with a gradient blob. No pills/tags overlaid on images (caption below or nothing), no photo-credit captions as decoration, no version footers, no scroll cues, no hero version labels unless the brief is a launch.

## 10. Redesign mode (brownfield)

Detect mode first — ambiguous means ask once (preserve vs scratch). **Preserve:** modernize in place, audit first, extract tokens, move gradually. **Overhaul:** new visuals, preserve content and IA. **Greenfield:** baseline dials, no audit needed.

Audit before touching: brand tokens (colors, type, logo, radii — a purple brand stays purple), IA tree and conversion paths, content blocks (working vs filler), existing patterns to preserve vs retire, SEO baseline (ranking pages, meta, structured data, OG — SEO migration is the #1 redesign risk). Preservation rules: IA/slugs/anchors/nav labels stable unless asked; copy voice preserved (visual refresh ≠ rewrite); keep accessibility wins; never rename analytics-tracked buttons/fields/IDs; never silently change URL slugs, form names/order, wordmarks, or legal/consent copy.

Fix in risk order for maximum impact per risk: (1) font swap, (2) color cleanup, (3) hover/active states, (4) layout and spacing, (5) generic component swaps, (6) loading/empty/error states, (7) type-scale polish. Working rules: existing stack stays (no framework migration; vanilla CSS if there is no framework; check Tailwind v3 vs v4 before touching config); test after every change; small reviewable diffs over rewrites. Upgrade levers, in order, stopping when satisfied: typography refresh → spacing/rhythm → color recalibration → motion layer → hero/key recomposition (vocabulary below) → full block replacement only if unsalvageable.

Also cover the unglamorous: semantic HTML (`nav/main/article/section`, no div soup), alt text on meaningful images, meta/OG tags, favicon, legal links, back-navigation on every page, branded 404, client-side form validation, skip-to-content link, cookie consent where required, no commented-out dead code, no hallucinated imports.

Reference vocabulary (patterns to reach for in recomposition): heroes — Asymmetric Split, Editorial Manifesto, Media Mask, Kinetic Type, Curtain Reveal, Scroll-Pinned; nav — floating glass pill, Dynamic Island, mega-menu reveal, contextual radial; layout — Bento, Masonry, Split-Screen Scroll, Sticky-Stack; cards — parallax tilt, spotlight border, morphing modal; scroll — horizontal hijack, zoom parallax, progress path; galleries — coverflow, drag-to-pan, accordion slider; text — kinetic marquee, mask reveal, scramble, circular path; micro — particle button, pull-to-refresh, shimmer skeleton, ripple, animated line-draw. Motion default `motion/react`; GSAP+ScrollTrigger for scrolltelling in isolated leaves; Three.js for canvas/3D under the same isolation.

## 11. Pre-flight (every box or not done)

Brief one-liner declared; dials explicit and reasoned; system chosen honestly (§2) or aesthetic labeled; redesign mode + audit if brownfield. Zero `—`/`–` separators page-wide. One theme (theme lock), one accent (color lock), one radius scale (shape lock), one icon family, one copy register. Button + form contrast AA. No wrapped desktop CTA; no duplicate CTA intent. Serif discipline held; premium palette rotated (no beige+brass default). Italic descenders cleared. Hero fits viewport (≤2-line headline, ≤20-word sub, CTAs without scroll, `pt-24` max, ≤4 text elements, logo wall below and logo-only). Eyebrows ≤1 per 3 sections; no split-header; zigzag ≤2 consecutive; layout families ≥4 per 8 sections; bento rhythm with exact N-cells and varied surfaces. Real images everywhere (or explicit TODOs); no pills on images, no fake UI, no version footers, no scroll cues, no decorative dots, no hero-bottom decoration strips. Density sane; quotes clean; lists use real components. Motion motivated and actually shipped if MOTION > 4; marquee ≤1; GSAP skeletons correct (`start:"top top"`, pinned, scrubbed, cleaned up); no scroll listeners; reduced-motion honored above 3; both color modes tested; mobile collapse explicit per section; `min-h-[100dvh]`; effect cleanups; empty/loading/error states present. Cards only where hierarchy demands. No banned fonts/icons/shadows/layouts from §1 archetypes' inverses. Vitals plausible. One design system per project. A single unticked box = fix before delivering.
